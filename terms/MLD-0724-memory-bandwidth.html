Memory bandwidth

The rate at which data can be transferred to or from a memory system.

Expanded guide · editorial review 2026-11-03. Original definitions, examples, notes and citations are preserved below. New examples are illustrative, not benchmark results.

Prerequisites

  • Floating-point operation count
  • Throughput

Where bandwidth enters an AI computation

A processor must move instructions, activations, weights and intermediate tensors through a hierarchy of storage. Memory bandwidth measures the rate of this movement at a named level: DRAM, device HBM, cache, a bus or a network link. A fast arithmetic unit can sit idle when the relevant bytes arrive too slowly; the identity of the limiting level must be measured, not assumed.

Peak specification versus achieved bytes per second

Theoretical bandwidth describes an interface under ideal transfers, not the sustainable throughput of an arbitrary kernel. Effective bandwidth from a timed operation is (bytes read + bytes written) / elapsed seconds. The same experiment must count transfers consistently and distinguish decimal GB (10^9 bytes) from binary GiB (2^30 bytes). Cache hits, noncoalesced requests, contention and protocol overhead affect achieved bandwidth.

Worked matrix-copy arithmetic

A synthetic copy of a 2048 by 2048 float32 matrix nominally reads and writes 4,194,304 values, or 33,554,432 bytes combined. If timing the device kernel alone took 0.0007 seconds, the illustrative effective rate is 33,554,432 / 0.0007 / 10^9 = 47.93 GB/s. Neither that duration nor that rate is a real measurement; read/write traffic and host-to-device copies must be accounted for separately.

Roofline bound and the bottleneck threshold

For arithmetic intensity I measured in FLOP/byte and usable bandwidth B in byte/s, the memory roof is I times B FLOP/s. With an assumed I = 2 FLOP/byte and B = 400 GB/s, the ceiling is 800 GFLOP/s, even if the hardware advertises 10 TFLOP/s. The roofline bound is an estimate for this chosen level of traffic; it is neither a benchmark result nor proof that a particular kernel reaches that ceiling.

LLM inference and model weight traffic

An illustrative 7-billion-parameter model with 2 bytes per stored weight occupies about 14 GB before overhead. If every weight were streamed once per generated token over a 1 TB/s memory channel, weight traffic alone implies a 14 ms lower bound for that simplified step. Actual token latency depends on cache, batching, quantization, architecture, KV-cache reads, kernel scheduling, compute and communication; the estimate is not a model latency forecast.

How to measure rather than guess

Profile representative shapes, batch sizes and sequence lengths after warm-up and synchronization. Record kernel durations, DRAM bytes, L2/L1 hit rates, occupancy and relevant tensor-core counters using tools such as Nsight Compute; include uncertainty across repeated runs. Compare achieved rates to the correctly scoped peak and evaluate end-to-end latency separately from individual kernels.

When moving fewer bytes beats a faster memory bus

Fusion can keep intermediate tensors on-chip; tiling and reuse can reduce external traffic; lower-precision formats can shrink model weights. These improvements may be limited by register pressure, conversions, cache behavior or accuracy requirements. Test the unfused and fused paths with identical outputs and workloads; a lower reported byte count is not automatically a faster application.

Near-memory hardware is a different design choice

In a November 2 research announcement, Tohoku University and AISIN described storing boot data and Tiny YOLOv3 weights in 32 MB of embedded STT-MRAM on a prototype chip. They reported a 65.7 ms operating-system boot, 124.2 ms from power-on to first detection, and 50.7 mJ per frame. This is publisher-reported, configuration-specific evidence about avoiding external transfers, not a claim that STT-MRAM universally offers higher HBM bandwidth or a commercial deployment.

Common mistakes and decision criteria

Do not equate larger peak GB/s with lower latency, count a cached byte as an off-chip transfer, or compare TFLOP/s without arithmetic intensity and precision. Start by locating the bottleneck for the target workload, then compare memory traffic, runtime and output quality before and after a change. Report device, driver, shapes, measurement scope and confidence limits so an independent team can attempt reproduction.
