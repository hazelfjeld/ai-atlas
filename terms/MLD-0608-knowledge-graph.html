Retrieval and search · MLD-0608

Knowledge graph

A structured representation of entities and relations, often with typed edges.

Expanded guide · editorial review 2026-11-02. Original definitions, examples, notes and citations are preserved below. New examples are illustrative, not benchmark results.

Prerequisites

  • Embedding
  • Semantic search
  • Retrieval-augmented generation
  • Tool use

Mechanism: represent meaning as linked facts

A knowledge graph identifies entities and stores typed relationships between them, such as (model, trained_on, dataset) or (claim, supported_by, paper). RDF is one common standard: its basic structure is a subject-predicate-object triple. Other property graphs use nodes, labeled edges and attributes. Graph structure supports explicit joins and provenance but does not guarantee factual correctness.

Why a graph differs from vector retrieval

An embedding search ranks items by similarity in a learned vector space; it does not enforce that a specific edge or business rule is true. A graph traversal can require that the retrieved product belongs to an authorized account and that an evidence record supports its attributes. Hybrid retrieval often uses both: embeddings identify candidates, and typed relationships constrain or explain a result.

Worked example: conflicting revenue definitions

Suppose two departments both label a metric 'revenue' while one excludes refunds and the other includes them. A semantic catalog can represent each metric's owning team, formula, version, data table and lineage. When an agent asks for quarterly revenue, it should resolve the correct metric definition and permission scope before generating SQL. A graph alone cannot choose the correct meaning without documented organizational policy.

RDF query sketch and relationship traversal

In RDF-style notation, (reportA, usesMetric, netRevenue) and (netRevenue, definedBy, financePolicyV3) are separate assertions. A SPARQL-style graph pattern requiring both edges can retrieve reports whose metric is backed by financePolicyV3. In a property graph, the analogous operation traverses labeled edges. This is illustrative pseudocode, not a literal query evaluated against a dataset.

From metadata to an ontology layer

An ontology specifies entity classes, relation meanings, constraints or shared vocabulary; a knowledge graph contains concrete assertions that may follow that ontology. NVIDIA Auto Ontology describes generating and reconciling such context from enterprise metadata, exposing it through APIs, CLI and MCP. 'Semantic ontology layer' is a descriptive architecture phrase, not a universally standardized new term or evidence of an independently verified SQL reliability gain.

Applications in AI systems

Graphs help with citation-linked research maps, dependency and supply-chain tracing, organizational data catalogs, knowledge-grounded retrieval, and validation of structured queries. They are especially helpful when relationships, provenance and permissions are first-class questions. Simple keyword search, a relational join or a vector store may be cheaper and adequate for smaller or weakly connected tasks.

Measuring quality before adopting a graph

Construct a gold set of entity IDs, relation labels, source citations and permitted query outcomes. Measure entity-resolution precision/recall, edge correctness, stale or orphan references, query accuracy, latency and cost under changed schemas. Run ablations comparing search-only, relational, graph-only and hybrid retrieval with the same questions; keep evaluation labels independent of graph-generation prompts.

Trust and security boundaries

Treat source documents, inferred edges and automatically generated SQL as untrusted until checked. Attach source IDs and timestamps to claims, enforce access control at the database/query layer, and audit who approved definitions and edits. The NVIDIA Auto Ontology project explicitly notes that its FastAPI internal identity header relies on a trusted gateway; exposing that internal service directly is unsafe, regardless of how useful the ontology is.

Limitations and common misconceptions

Graph edges can encode stale, biased or hallucinated associations; an apparently explainable path is not automatically causal or correct. Store assertion timestamps and source-level review labels to make those failure modes inspectable. Entity resolution is difficult when names collide, and ontologies require governance when organizations redefine metrics. A knowledge graph is not necessarily RDF, an LLM, a vector database, or proof that every generated answer is grounded. Report which links are asserted, inferred or reviewed.
