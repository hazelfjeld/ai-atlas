Evaluation metrics and uncertainty · MLD-0386

Exact match

The fraction of outputs matching reference answers under stated normalization rules.

Expanded guide · editorial review 2026-11-03. Original definitions, examples, notes and citations are preserved below. New examples are illustrative, not benchmark results.

Prerequisites

  • Accuracy
  • Answer normalization
  • Structured output

Exact match is a comparison rule, not a universal truth metric

For N evaluated tasks, task-level exact match is the count of predictions that match their gold targets according to a predeclared normalization rule, divided by N. Equivalently, EM = (1/N) sum of indicator(normalize(prediction_i) = normalize(reference_i)). A perfect EM requires all compared elements to agree, but what counts as an element and which normalizations are allowed must be specified in advance.

Worked calculation on complete JSON records

In a synthetic four-task extraction test, suppose three outputs match their references after approved key-order normalization and one output contains a wrong status code. Whole-record exact match is 3/4 = 75%. If the four records each contain five fields and only one field is wrong, field accuracy is 19/20 = 95%. These are constructed numbers, not a model evaluation or claim about any public benchmark.

Semantic normalization must be task-specific

Whitespace trimming can be appropriate for some short-answer tasks, while changing case, punctuation, unit notation, numeric precision or Unicode normalization can erase meaningful differences in others. In structured records, object key order may be irrelevant while array order can represent chronology or priority. Pre-register the canonicalization algorithm and preserve raw outputs so evaluators can audit what was ignored.

Exact match versus schema and parse validity

Consider a required JSON object with status as an integer and user as a string. An output with the wrong but valid integer status can be parseable and schema-compliant while failing exact match against the reference. Conversely, a harmless difference in object-property order may fail naïve byte-for-byte matching while representing the same parsed object. Report parse success, schema validity, exact match and semantic field accuracy as separate metrics.

Why all-fields-correct falls with more fields

Under a deliberately simplifying assumption that five field predictions are independent and each is correct with probability 0.95, a complete five-field record is perfect with probability 0.95^5 = 0.774. With 20 such fields the product becomes 0.95^20 = 0.358. Real errors are often correlated, so these toy calculations are intuition for strict scoring rather than empirical performance predictions.

Choose aggregation before reading outcomes

Micro field accuracy counts all correctly predicted fields and weights tasks with many fields more heavily. Macro averaging gives each task or grammar equal weight before averaging. For whole-task EM, say whether malformed outputs count as failure, whether multiple valid reference targets exist and how abstentions are handled. Report task counts and confidence intervals rather than only a single headline percentage.

A controlled evaluation protocol

Freeze the dataset, reference values, canonicalizer, model revision, generation settings and scoring code before an untouched holdout run. Validate the judge with unit cases for key ordering, null versus absent, floating-point rounding, duplicate fields and Unicode. Keep a predeclared failure taxonomy and inspect random samples of both passes and failures. Never tune the normalization rule on the test outputs.

What exact match measures badly

A valid paraphrase of a natural-language answer can fail string EM despite conveying the same meaning. Conversely a copied phrase can match while unsupported by the evidence. In safety-critical extraction, a high mean EM might hide rare but severe field errors or subgroup failures. Pair exact match with field-level diagnostics, evidence-grounded manual audits, and downstream decision-impact tests.

Relating IFParse-style telemetry tasks to real-world systems

IFParse v2.0's author describes a synthetic, strict JSON field-extraction benchmark across several telemetry grammars. It highlights the difference between valid JSON and all-fields-correct evaluation, but this Atlas review has not independently audited its pinned dataset card, reproduced the scores or established transfer to real private logs. An exact-match score alone is not a production deployment validation.

Practical selection and interpretation

Use strict EM for tasks with a genuinely canonical output such as a normalized identifier, deterministic structured transformation or precisely specified schema. When outputs admit legitimate alternatives, add a semantic equivalence check that is itself testable and transparent. Preserve the source, oracle, normalization version, model outputs and review date so a later correction can be traced without rewriting the original result.
