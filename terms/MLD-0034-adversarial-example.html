Security, privacy, and fairness · MLD-0034

Adversarial example

An input deliberately modified to induce a model error under a specified perturbation model.

Expanded guide · editorial review 2026-11-02. Original definitions, examples, notes and citations are preserved below. New examples are illustrative, not benchmark results.

Prerequisites

  • Adversarial evaluation

What makes an example adversarial

An adversarial example is an input deliberately changed to trigger a model error, with the change constrained by an explicit threat model. A difficult naturally occurring example is not automatically adversarial; intent, selection, permitted transformations and desired outcome matter.

The mechanism in classification

Let f map an input x to a predicted label y. A test constructs x' = x + delta, chooses delta from an allowed set S, and looks for f(x') to differ from the correct label. A small pixel-space distance alone does not prove the semantics or ground-truth class was preserved.

A completely synthetic worked example

Imagine a toy classifier assigning 0.55 probability to a positive class for a vector with coordinates [0.20,0.50]. An authorized perturbation produces [0.18,0.50], changing its decision to 0.49. The 0.02 input change and scores are invented to illustrate a boundary crossing, not an experiment.

Fast-gradient-sign intuition

For differentiable loss L(theta,x,y), the fast gradient sign method constructs delta = epsilon * sign(gradient_x L), then clips to valid input bounds. The sign points toward a locally loss-increasing direction under an L-infinity budget; this is an attack candidate, not a universal proof of failure.

Distance budgets and semantic validity

An L-infinity bound of epsilon restricts every input coordinate independently; an L2 bound restricts total Euclidean change. Neither guarantees that a human regards the modified sample as the same object or that a changed medical measurement remains clinically plausible. Specify encoding, scaling and allowed features.

White-box, transfer and query-based settings

A white-box evaluator may access model gradients; a transfer evaluator generates candidates with a surrogate; a query-based evaluator observes outputs subject to a budget. These imply different capabilities and cannot be compared fairly without reporting access, iteration counts, randomness and query limits.

How to test a claimed defense

Separate clean accuracy from accuracy under a prespecified attack suite, use a frozen and disjoint evaluation set, and include adaptive attacks suited to the defense. One failed gradient attack is not evidence of robustness: randomization, non-differentiability and masked gradients can hide vulnerability.

Safety and scope of conclusions

Adversarial examples show model behavior under a defined input manipulation, not evidence that a deployed adversary exploited the model. Report the domain, norm, perturbation budget, success criterion and sample provenance. Avoid extrapolating from toy images to all text, sensor and agent attacks.

A reproducible comparison protocol

On authorized test data, choose perturbation sets before seeing results, freeze preprocessing and model checkpoints, evaluate multiple attack families and random seeds, and record clean and attacked accuracy with intervals. Audit manipulated labels for semantic stability and publish failure examples without sensitive data.
