Security, privacy, and fairness · MLD-0549

Indirect prompt injection

Prompt injection delivered through external material rather than a direct instruction from the legitimate user.

Expanded guide · editorial review 2026-11-02. Original definitions, examples, notes and citations are preserved below. New examples are illustrative, not benchmark results.

Prerequisites

  • Prompt injection
  • Agentic workflow
  • Retrieval-augmented generation
  • Red teaming

What makes an injection indirect

In indirect prompt injection, an attacker plants instruction-like material in data the defender will read while serving a legitimate request. The attacker may control a web page, email body, PDF passage or tool-output field but does not need to send a direct message to the agent. The trust failure occurs if source content is obeyed as a higher-priority command.

Entry points and the untrusted-data path

A typical path is user request → retrieval or tool response → model context → proposed answer or tool call. A malicious instruction can sit in search results, a code comment or a knowledge-base entry. The adversary's control is limited to that lower-trust surface; documenting its scope matters because a poisoned tool response is not the same as compromising the tool server itself.

Why retrieval can cross the authority boundary

Retrieval-augmented generation is designed to make external text visible at answer time, not to make that text authoritative about tool use. An attacker can mix legitimate facts with an instruction to change the task or fabricate a policy claim. Cite and summarize the retrieved facts while keeping authorization tied to the user and application; the passage's 'system' label is merely source text.

Synthetic example with a document summarizer

Suppose a student asks an assistant to summarize a publicly available research note. A paragraph within it says that the summary must promote a particular unrelated product. If the assistant repeats that endorsement as an instruction-following behavior, the attacker has contaminated the answer. The invented demonstration involves no actual product or measured model, and does not imply a real incident.

Synthetic example with side effects

A workplace agent reads an email containing a forged instruction to change a meeting time. The correct process is to classify it as email content, summarize what the sender wrote and require the authenticated user's actual scheduling intent and permissions before editing a calendar. Only an audited write to the calendar state would establish an unauthorized action; a model's claim that it changed the meeting would not.

Scope-aware controls and information flow

Separate retrieved text from policy, label provenance in logs and require permission checks at the execution boundary. Restrict what data and tools an agent can access, avoid passing sensitive context into unrelated tool calls, and require approval for irreversible actions. Quoting, delimiters, prompt hardening and injection detectors can assist but are not themselves access control or guarantees.

Evaluation methodology: both goals matter

AgentDojo provides a research example of stateful agent tasks combined with attacker-controlled tool responses and programmatic success checks. For an app-specific test, track legitimate task utility and targeted attack success independently. Use resettable isolated environments and adversarial variants; a defense may lower attack success while also blocking harmless tasks, so measure false refusals and latency.

Worked diagnostic confusion matrix

Imagine 40 synthetic documents: 10 contain planted attack text and 30 are benign. A detector flags 8 of the 10 attacks and also flags 6 benign cases; its attack recall is 8/10 = 80% and its benign false-positive rate is 6/30 = 20%. Those illustrative numbers test the detector only, not the downstream agent's behavior, and are not published benchmark measurements.

Evidence limits and reporting discipline

The 2023 indirect-injection paper reports experimental attacks on selected integrated systems, while OWASP groups a broader class of risks and AgentDojo measures controlled tasks. Neither proves that an arbitrary current deployment was compromised. Report observed side effects, permission failures, version and test conditions; distinguish attempted injection, successful steering, unauthorized action and confirmed real-world incident.
